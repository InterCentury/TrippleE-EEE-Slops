## 1. Project 1: Automated Smart Light Controller (LDR to LED Interface)

This project constructs an automated industrial style lighting switch. The subsystem reads ambient illumination levels via a photoresistor (LDR) and dynamically drives a high-efficiency digital output line when light falls below a software-defined threshold boundary.

### 1.1 Structural Hardware Wiring Topology

The system uses an analog voltage divider input paired with a digital current-sourcing output network.

```text
  System Excitation Rail (5V) ─────────────────┬───────────────────────────────┐
                                               │                               │
                                     [ Photoresistor (LDR) ]             [ Status LED ]
                                               │                               │ (Anode)
                                               ├───────► ADC Input (Pin A0)    │ (Cathode)
                                               │                               ▼
                                     [ Fixed 10kΩ Resistor ]         [ Fixed 220Ω Resistor ]
                                               │                               │
  System Ground Floor (GND) ───────────────────┴───────────────────────────────┴─────────────

```

### 1.2 Mathematical Threshold Calculus

To minimize electrical "chattering" (rapid, erratic switching when ambient light hovers precisely at the trip point), the firmware enforces **Software Hysteresis**. Instead of a single threshold value, the system establishes two discrete switching limits:

$$V_{\text{turn\_on}} = V_{\text{CC}} \cdot \frac{R_{\text{dark}}}{R_1 + R_{\text{dark}}}$$

$$V_{\text{turn\_off}} = V_{\text{CC}} \cdot \frac{R_{\text{light}}}{R_1 + R_{\text{light}}}$$

When ambient light decreases, the LDR resistance ($R_{\text{sensor}}$) increases, causing the voltage across it in a pull-down configuration to change. We map these voltages directly to 10-bit digital integer bounds:

* **Deactivation Boundary Threshold (`THRESHOLD_HIGH`):** Set to a raw code of `700` (~3.42V). The light turns off only when brightness exceeds this point.
* **Activation Boundary Threshold (`THRESHOLD_LOW`):** Set to a raw code of `400` (~1.95V). The light turns on only when brightness drops below this point.

### 1.3 Bare-Metal Firmware Implementation

```cpp
#define LDR_PIN        A0    // Analog input pin connected to the divider node
#define RELAY_LED_PIN  13    // Digital output pin driving the active load

#define THRESHOLD_LOW  400   // Lower activation limit (Darkness limit)
#define THRESHOLD_HIGH 700   // Upper deactivation limit (Brightness limit)

enum SystemState { LIGHTS_OFF, LIGHTS_ON };
SystemState current_state = LIGHTS_OFF;

void setup() {
    pinMode(RELAY_LED_PIN, OUTPUT);
    pinMode(LDR_PIN, INPUT);
    digitalWrite(RELAY_LED_PIN, LOW); // Default load to off state
}

void loop() {
    // 1. Acquire the quantized illumination voltage level
    int raw_ambient = analogRead(LDR_PIN);

    // 2. Evaluate state transitions using a finite state machine with hysteresis
    switch (current_state) {
        case LIGHTS_OFF:
            if (raw_ambient < THRESHOLD_LOW) {
                digitalWrite(RELAY_LED_PIN, HIGH);
                current_state = LIGHTS_ON;
            }
            break;

        case LIGHTS_ON:
            if (raw_ambient > THRESHOLD_HIGH) {
                digitalWrite(RELAY_LED_PIN, LOW);
                current_state = LIGHTS_OFF;
            }
            break;
    }
    delay(50); // Small loop stabilization delay
}

```

## 2. Project 2: High-Resolution DC Motor Speed Regulator (Potentiometer to PWM)

This design implements an open-loop motor velocity driver. The position of an analog potentiometer is mapped to a high-frequency hardware Pulse Width Modulation (PWM) duty cycle, which controls power delivery to a DC motor via an isolated transistor driver stage.

### 2.1 Hardware Schematic and Flyback Isolation Topology

Because DC motors generate destructive back-EMF voltage spikes during switching, the digital control circuitry must be protected by an isolation transistor stage and a parallel flyback diode.

```text
  External Power Rail (12V) ───────────────────────────┬──────────────────────┐
                                                       │                      │
                                               [ DC Motor Load ]     [ Flyback Diode ]
                                                       │ (Drain)              ▲ (Cathode)
                                                       ├──────────────────────┴───────
                                                       │
  PWM Output Pin (Pin 6) ───► [ 100Ω Resistor ] ───► [ Gate ]  (N-Channel MOSFET)
                                                       │ (Source)
  System Ground Floor (GND) ───────────────────────────┴──────────────────────────────

```

### 2.2 Governing Domain Mapping Formulas

The continuous position of the potentiometer is sampled by a 10-bit ADC, returning an integer range from `0` to `1023`. The internal hardware timer generating the single-slope Fast PWM wave operates on an 8-bit register, restricting its input range from `0` to `255`.

The linear mapping function translates the raw input code to the target output register value:

$$\text{PWM}_{\text{register}} = \text{round}\left( ADC_{\text{value}} \cdot \frac{255}{1023} \right) = \text{round}\left( \frac{ADC_{\text{value}}}{4} \right)$$

The effective average DC voltage ($V_{\text{avg}}$) delivered across the motor winding coils scales directly with this duty cycle percentage ($D$):

$$D = \frac{\text{PWM}_{\text{register}}}{255} \times 100\%$$

$$V_{\text{avg}} = V_{\text{motor\_rail}} \cdot D = 12.0\text{V} \cdot \left( \frac{\text{PWM}_{\text{register}}}{255} \right)$$

### 2.3 Bare-Metal Firmware Implementation

```cpp
#define POT_PIN        A1    // Potentiometer slider analog interface node
#define MOTOR_GATE_PIN 6     // Timer 0 Compare Channel A Hardware PWM Output Pin

void setup() {
    pinMode(MOTOR_GATE_PIN, OUTPUT);
    pinMode(POT_PIN, INPUT);
    
    // Low-level configuration of Timer 0 for Fast PWM on Pin 6 (Non-Inverting)
    TCCR0A = (1 << COM0A1) | (1 << WGM01) | (1 << WGM00);
    TCCR0B = (1 << CS01) | (1 << CS00); // Prescaler N = 64
}

void loop() {
    // 1. Acquire the 10-bit analog control position value
    int pot_input = analogRead(POT_PIN);

    // 2. Perform scaling transformation to map 10-bit input to 8-bit output
    int pwm_duty = pot_input / 4; // Integer bit-shift equivalent to linear division

    // 3. Update the hardware Output Compare Register to adjust the duty cycle
    OCR0A = pwm_duty; 
}

```

## 3. Project 3: Closed-Loop Thermal Monitor with Audible Threshold Alarm

This system monitors ambient temperature using a precision analog NTC thermistor network. If the calculated physical temperature exceeds a predefined critical safety threshold, the firmware activates an audible alarm using a hardware-driven piezo buzzer module.

### 3.1 Closed-Loop Alarm Interfacing Layout

```text
  System Excitation Rail (5V) ─────────────────┬───────────────────────────────┐
                                               │                               │
                                     [ NTC Thermistor ]               [ Piezo Buzzer ]
                                               │                               │ (+)
                                               ├───────► ADC Input (Pin A2)    │ (-)
                                               │                               ▼
                                     [ Fixed 10kΩ Resistor ]         [ GPIO Output (Pin 8) ]
                                               │                               │
  System Ground Floor (GND) ───────────────────┴───────────────────────────────┴─────────────

```

### 3.2 Thermodynamic Linearization Math

The system converts the raw analog reading from the thermistor divider into an accurate temperature value using the third-order polynomial **Steinhart-Hart Equation**:

$$\frac{1}{T} = A + B \cdot \ln(R_{\text{sensor}}) + C \cdot [\ln(R_{\text{sensor}})]^3$$

$$T_{^\circ\text{C}} = T - 273.15$$

Where the instantaneous resistance ($R_{\text{sensor}}$) is computed dynamically from the raw 10-bit digital value ($ADC_{\text{value}}$):

$$R_{\text{sensor}} = 10000.0 \cdot \left( \frac{ADC_{\text{value}}}{1023.0 - ADC_{\text{value}}} \right)$$

### 3.3 Bare-Metal Firmware Implementation

```cpp
#include <math.h>

#define THERMISTOR_PIN   A2    // Input node of the thermistor-divider circuit
#define ALARM_BUZZER_PIN 8     // Digital output node driving the piezo transducer

#define CRITICAL_TEMP    45.0  // Upper safety threshold boundary in Celsius

// Empirical Steinhart-Hart Coefficients for 10k Thermistor at 25°C
const double A = 0.001129148;
const double B = 0.000234125;
const double C = 0.0000000876741;

void setup() {
    pinMode(ALARM_BUZZER_PIN, OUTPUT);
    pinMode(THERMISTOR_PIN, INPUT);
    digitalWrite(ALARM_BUZZER_PIN, LOW);
}

void loop() {
    int raw_adc = analogRead(THERMISTOR_PIN);

    // Prevent divide-by-zero errors at boundary limits
    if (raw_adc > 0 && raw_adc < 1023) {
        // 1. Calculate the instantaneous resistance of the thermistor
        double r_sensor = 10000.0 * ((double)raw_adc / (1023.0 - (double)raw_adc));

        // 2. Linearize resistance data into absolute thermodynamic Kelvin units
        double ln_r = log(r_sensor);
        double inv_k = A + (B * ln_r) + (C * ln_r * ln_r * ln_r);
        double temp_celsius = (1.0 / inv_k) - 273.15;

        // 3. Evaluate the safety limit condition
        if (temp_celsius >= CRITICAL_TEMP) {
            // Generate an audible alarm oscillation (Square wave output)
            digitalWrite(ALARM_BUZZER_PIN, HIGH);
            delay(1);
            digitalWrite(ALARM_BUZZER_PIN, LOW);
            delay(1);
        } else {
            digitalWrite(ALARM_BUZZER_PIN, LOW);
        }
    }
}

```

## 5. Summary Summary Checklist

1. **Software Hysteresis Protection:** Dual-threshold switching loops prevent control relays from rapidly chattering when analog inputs hover close to a single threshold point.
2. **Back-EMF Isolation Requirements:** Switching high-current inductive loads (like DC motors) requires parallel flyback diodes to safely divert high-voltage inductive spikes away from the MCU.
3. **Data Resolution Scaling:** Interfacing 10-bit analog inputs with 8-bit PWM outputs requires linear scale compression, which can be optimized in firmware using fast bit-shift division operations.
4. **Thermodynamic Calculation Blocks:** Non-linear sensor data streams must be processed using precise curve-fitting models like the third-order Steinhart-Hart equation to calculate accurate engineering units.
5. **Zero-Division Exception Guards:** Embedded processing code must use input validation boundary checks to intercept full-scale data extremes, avoiding critical mathematical runtime errors.
6. **Finite State Structuring:** Structuring control routines as explicit finite state machines simplifies development and improves code reliability in complex mixed-signal systems.
7. **Current Limitation Protection:** Low-impedance status indicators must always be paired with series current-limiting resistors to prevent overloading the output driver transistors.
8. **Hardware Timer Utilization:** Offloading PWM generation to dedicated internal hardware timer registers keeps the primary application loop free to handle other monitoring tasks.
9. **Transistor Switching Drivers:** Low-power GPIO pins cannot drive high-current loads directly, requiring external transistor buffers (such as power MOSFETs) to switch separate voltage rails.
10. **Low-Level Register Access:** Directly manipulating internal peripheral control registers bypasses slow framework abstraction layers, providing precise control over wave shapes and execution timing.
