# 11.05 - System Diagnostics: Hardware Troubleshooting and Firmware Debugging

## 1. The Diagnostic Hierarchy

Debugging an embedded electromechanical system requires a rigid, deterministic approach. Randomly altering C++ code or swapping components introduces unknown variables and compounds errors. System failures must be isolated by moving systematically up the abstraction layers: Power $\rightarrow$ Hardware Signals $\rightarrow$ Firmware Logic.

---

## 2. Layer 1: Power Rail and Continuity Verification

The majority of erratic robot or embedded system behavior stems from unstable power delivery, not flawed firmware.

### 2.1 The Common Ground Imperative

Voltage is a relative measurement (a potential difference). If a sensor, a microcontroller (MCU), and a high-current motor driver do not share a common, low-resistance ground plane, the logic signals will "float" relative to each other.

* **Diagnostic:** Switch a multimeter to Continuity Mode (beeper). With the system completely unpowered, place one probe on the MCU ground pin and the other on the motor driver ground pin. A continuous beep confirms a unified ground plane.

### 2.2 Voltage Sag and Brownouts

When inductive loads (motors) initiate, they draw a massive stall current ($I_{\text{stall}}$). If the internal resistance of the power supply or battery ($R_{\text{batt}}$) is too high, this current spike causes a severe voltage drop across the entire power rail.

$$V_{\text{rail}} = V_{\text{batt}} - (I_{\text{stall}} \cdot R_{\text{batt}})$$

If $V_{\text{rail}}$ drops below the MCU's minimum operating threshold (e.g., $3.3\text{V}$ or $2.7\text{V}$), the processor will instantly trigger a Brown-Out Reset (BOR).

* **Symptom:** The system runs normally until the motor is commanded to move, at which point the MCU restarts, re-running the `setup()` function infinitely.
* **Mitigation:** Add bulk decoupling capacitors (e.g., $470\text{ }\mu\text{F}$ to $1000\text{ }\mu\text{F}$ electrolytic) across the motor supply rails to supply instantaneous current and buffer the voltage sag.

## 3. Layer 2: Semiconductor and Signal Diagnostics

Once power is verified, the physical signaling between the MCU and the actuators/sensors must be tested.

### 3.1 PWM Signal Verification (Multimeter vs. Oscilloscope)

When debugging Pulse-Width Modulation (PWM) signals sent to a motor driver or MOSFET gate, standard multimeters can be deceiving.

A multimeter set to DC Voltage will average the high-frequency square wave. If the MCU outputs a $5\text{V}$ logic signal at a $50\%$ duty cycle ($D = 0.5$), the multimeter will read:

$$V_{\text{avg}} = V_{\text{logic}} \cdot D = 5\text{V} \cdot 0.5 = 2.5\text{V}$$

While this confirms a signal is present, it cannot diagnose signal integrity issues like ringing, slow rise times (due to gate capacitance), or frequency mismatches.

### 3.2 Floating MOSFET Gates

If a MOSFET activates erratically or refuses to shut off when the MCU pin is in a high-impedance state (e.g., during MCU boot sequence), the gate is floating. The microscopic capacitance of the gate ($C_{\text{iss}}$) traps environmental static charge.

```text
> MOSFET GATE PULL-DOWN DIAGNOSTIC SCHEMATIC

[MCU PWM] ────┬──────────────► [Gate] MOSFET
              │
             [R] 10kΩ Pull-Down Resistor (Crucial for state definition)
              │
             GND

```

* **Diagnostic Fix:** Ensure a $10\text{k}\Omega$ pull-down resistor is physically installed between the Gate and Ground to forcibly drain the gate charge when the MCU is not actively driving it high.

### 3.3 Catastrophic Flyback Failure

If the low-side switching MOSFET is physically destroyed (shorted internally from Drain to Source) after running a DC fan or motor, the primary suspect is a missing or backward Flyback Diode. Calculate the inductive spike using Faraday's law ($V = -L \cdot \frac{di}{dt}$); without a diode shunt, this infinite voltage spike punctures the silicon barrier.

## 4. Layer 3: C++ Firmware Telemetry and Logic States

If the hardware is electrically sound, the failure exists in the firmware logic. Isolate the logic from the hardware by extracting real-time variables.

### 4.1 Serial Telemetry (The Software Probe)

Use hardware UART (Serial communication) to stream internal mathematical states to a terminal. For closed-loop systems (like the Line Follower PID or Thermistor project), print the raw ADC input alongside the calculated output.

```cpp
// Diagnostic Telemetry for PID Control Loop
Serial.print("Raw_Pos:");
Serial.print(error);
Serial.print("\t P_Term:");
Serial.print(P);
Serial.print("\t D_Term:");
Serial.print(D);
Serial.print("\t Final_PWM:");
Serial.println(U);

```

* **Analysis:** If `Final_PWM` exceeds 255 but the motor slows down, it indicates an 8-bit integer overflow. The firmware is missing a `constrain()` function.

### 4.2 State Machine Deadlocks

For Reactive Navigation (Obstacle Avoidance), bugs often manifest as the robot freezing in one state. This occurs when the boolean logic required to transition out of a `switch/case` state is mathematically impossible to achieve.

* **Diagnostic:** Insert a state-announcement print at the exact moment the state changes (not continuously in the loop).
* **Isolation:** If the code recently broke after an update, utilize version control tools like `git bisect` on your repository to perform a binary search through your commit history, instantly isolating the exact C++ commit that introduced the navigation deadlock.

---

## 5. Standard Diagnostic Checklist

1. **The Smoke Test:** Power the circuit and physically touch the ICs and voltage regulators. If a component is hot enough to burn your finger, immediately cut power. You have a direct short circuit.
2. **Isolate the Subsystem:** Do not test the PID algorithm, the motor drivers, and the IR array simultaneously. Write a standalone script to test *only* the motors, then *only* the sensors.
3. **Verify ADC Resolution:** Ensure your math matches the hardware. An Arduino Uno has a 10-bit ADC ($0$ to $1023$), while modern ARM chips often use 12-bit ADCs ($0$ to $4095$). Using 10-bit math on a 12-bit MCU will cause all sensor readings to appear catastrophically wrong.
4. **Inspect $\Delta t$ in Calculus Functions:** For PID or velocity integration, if the execution timer (`millis()`) delta is accidentally reading as $0$ due to a fast loop, the derivative division ($\frac{de}{dt}$) will trigger a divide-by-zero hardware exception, silently freezing the MCU.
