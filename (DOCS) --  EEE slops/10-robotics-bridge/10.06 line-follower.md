# 10.06 - Autonomous Line Tracking: Sensor Arrays and PID Control Systems

## 1. The Closed-Loop Navigation Paradigm

A line-following robot operates as a continuous closed-loop control system. It utilizes an array of downward-facing infrared (IR) reflectance sensors to detect a high-contrast path (e.g., black electrical tape on a white floor) and feeds this spatial data into a microprocessor. The processor calculates the vehicle's deviation from the center of the line and dynamically adjusts the differential wheel velocities to force the physical error back to zero.

To achieve fluid, non-oscillating movement at high speeds, simple binary (bang-bang) control (e.g., "if left sensor sees line, turn left") is vastly insufficient. The system mandates a **Proportional-Integral-Derivative (PID)** control algorithm.

---

## 2. Sensor Array Geometry and Error Quantization

To apply proportional math, the robot must know exactly *how far* off-center it is, not just that it is off-center. This requires multiple IR sensors arranged linearly across the chassis bow.

### 2.1 The Weighted Average (Center of Mass) Algorithm

Assume a standard 5-channel IR sensor array. To calculate a singular, continuous positional value, we assign a mathematical weight ($W_i$) to each sensor corresponding to its physical distance from the center axis.

```text
> 5-CHANNEL SENSOR ARRAY GEOMETRY

  [ S1 ]      [ S2 ]      [ S3 ]      [ S4 ]      [ S5 ]
  Far Left    Mid Left    Center      Mid Right   Far Right

  Weight:     Weight:     Weight:     Weight:     Weight:
  -2000       -1000         0         +1000       +2000

```

The algorithm reads the analog voltage or digital pulse width from each sensor ($V_i$) and calculates the weighted average. Assuming higher values mean "darker" (seeing the line):

$$\text{Position} = \frac{\sum_{i=1}^{5} (V_i \cdot W_i)}{\sum_{i=1}^{5} V_i}$$

* **Dead Center:** If S3 reads a high value and the others read 0, Position = $0$.
* **Slight Right:** If S4 reads a high value, Position approaches $+1000$.
* **Straddling:** If S2 and S3 read equally, Position is exactly $-500$.

Because the objective is to keep the line perfectly centered, our **Setpoint (SP)** is always $0$. Therefore, the **Error ($e$)** at any given time ($t$) is simply the calculated Position.

$$e(t) = \text{Position} - \text{Setpoint} = \text{Position}$$

---

## 3. The PID Controller Mathematics

The PID controller evaluates the Error vector ($e(t)$) in three distinct temporal dimensions: Present, Past, and Future.

### 3.1 Proportional (P) - The Present

The proportional term applies a corrective force directly proportional to the current error. The further the robot drifts, the harder it steers back.

$$u_p(t) = K_p \cdot e(t)$$

* **Effect:** Drives the robot toward the line. Too much $K_p$ causes violent, aggressive oscillation (fishtailing).

### 3.2 Integral (I) - The Past

The integral term accumulates the sum of all past errors over time. It defeats "steady-state error" (e.g., if a motor is slightly weaker, the P-term alone might leave the robot running slightly off-center forever).

$$u_i(t) = K_i \cdot \int_{0}^{t} e(\tau) d\tau \approx K_i \cdot \sum e \cdot \Delta t$$

* **Effect:** Forces the error exactly to zero over time. In highly dynamic line followers, this term is often kept very small or at zero ($0$) to prevent "integral windup," which causes massive overshoots on sharp corners.

### 3.3 Derivative (D) - The Future

The derivative term calculates the rate of change of the error. It predicts where the error is going and acts as an electromagnetic shock absorber to damp out the proportional oscillations.

$$u_d(t) = K_d \cdot \frac{de(t)}{dt} \approx K_d \cdot \left( \frac{e(t) - e(t-1)}{\Delta t} \right)$$

* **Effect:** Resists sudden changes. If the robot is swinging rapidly back toward the center, the D-term will actually apply opposite force to "brake" the swing and prevent overshooting the line.

### 3.4 The Total Control Output

The three terms are summed to generate the master control variable ($U$), representing the total required steering correction.

$$U(t) = (K_p \cdot e(t)) + \left( K_i \cdot \sum e \cdot \Delta t \right) + \left( K_d \cdot \frac{\Delta e}{\Delta t} \right)$$

---

## 4. Differential Steering Kinematics (Motor Mixing)

The control variable $U(t)$ must be translated into actual pulse-width modulation (PWM) commands for the left and right DC motors.

The chassis requires a predefined base forward velocity ($V_{\text{base}}$). The control variable is added to one motor and subtracted from the other, creating a differential speed that induces rotation.

* **Positive Error (Line is to the right):** $U(t)$ is positive. We must turn right. We increase left motor speed and decrease right motor speed.
* **Negative Error (Line is to the left):** $U(t)$ is negative. We must turn left. We decrease left motor speed and increase right motor speed.

$$V_{\text{left}} = V_{\text{base}} + U(t)$$

$$V_{\text{right}} = V_{\text{base}} - U(t)$$

*Crucial Hardware Limit:* PWM registers are rigidly strictly 8-bit ($0$ to $255$). The mathematical output of the motor mixing must be hard-constrained to prevent integer overflow (which causes the motor to violently invert).

## 5. Bare-Metal C++ PID Firmware Implementation

```cpp
#include <Arduino.h>

// Tuning Constants (Must be determined empirically via trial and error)
const float Kp = 0.15;
const float Ki = 0.00; // Often 0 for high-speed followers
const float Kd = 1.20;

// Kinematic Limits
const int BASE_SPEED = 150;
const int MAX_SPEED = 255;
const int MIN_SPEED = 0;   // Set to negative if reverse thrust is allowed

// State Variables
float previous_error = 0;
float integral = 0;
unsigned long last_time = 0;

// --- Abstracted Hardware Functions ---
float read_sensor_array_error() {

    // Returns a value between -2000 (far left) and +2000 (far right)
    return calculate_position(); 
}

void set_motor_speeds(int left_pwm, int right_pwm) {
    // Implementation mapping to L298N/TB6612FNG drivers from Section 10.03
    // ...
}
// -------------------------------------

void execute_pid_loop() {
    unsigned long current_time = millis();
    float dt = (current_time - last_time);
    
    if (dt == 0) return; // Prevent divide-by-zero on ultra-fast loops

    // 1. Calculate Error
    float error = read_sensor_array_error();

    // 2. Proportional
    float P = Kp * error;

    // 3. Integral (with anti-windup constraint)
    integral += (error * dt);
    integral = constrain(integral, -1000, 1000); 
    float I = Ki * integral;

    // 4. Derivative
    float derivative = (error - previous_error) / dt;
    float D = Kd * derivative;

    // 5. Compute Control Variable
    float U = P + I + D;

    // 6. Motor Mixing
    int left_speed = BASE_SPEED + (int)U;
    int right_speed = BASE_SPEED - (int)U;

    // 7. Hardware Saturation Constraints
    left_speed = constrain(left_speed, MIN_SPEED, MAX_SPEED);
    right_speed = constrain(right_speed, MIN_SPEED, MAX_SPEED);

    // 8. Actuate
    set_motor_speeds(left_speed, right_speed);

    // 9. Store State for Next Iteration
    previous_error = error;
    last_time = current_time;
}

void loop() {
    execute_pid_loop();
}

```

## 6. Summary Checklist

1. **Closed-Loop Imperative:** Line following requires continuous negative feedback to zero out positional error; open-loop dead reckoning will fail instantly.
2. **Weighted Array Mathematics:** A sensor array must be mathematically reduced to a single spatial error value using a weighted center-of-mass algorithm, not binary logic statements.
3. **Proportional Oscillation:** The P-term provides the raw steering muscle. Over-tuning $K_p$ results in aggressive, sustained lateral oscillation (fishtailing).
4. **Derivative Damping:** The D-term acts as the suspension system. It dampens the P-term by applying reverse force as the robot rapidly approaches the center line, preventing overshoot.
5. **Integral Windup Danger:** The I-term accumulates error over time. On sharp 90-degree corners, this accumulation can "wind up" massively, causing the robot to wildly over-steer once it regains the line.
6. **Differential Mixing:** The PID control output $U(t)$ is mathematically added to one motor and subtracted from the other relative to a fixed $V_{\text{base}}$ velocity.
7. **PWM Saturation Clamping:** Firmware must explicitly use `constrain()` functions to ensure calculated motor speeds never drop below $0$ (unless H-bridge reversing is enabled) or exceed $255$ before writing to hardware registers.
8. **Loop Timing ($\Delta t$):** True PID requires consistent temporal execution. The derivative term is highly sensitive to variations in $\Delta t$; therefore, `dt` must be actively measured using hardware timers, not assumed.
