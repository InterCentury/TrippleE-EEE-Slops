# 10.03 - The L298N Dual H-Bridge: Architecture, Thermal Loss, and Bare-Metal Control

## 1. Legacy Silicon: The L298N BJT Dual H-Bridge

The STMicroelectronics L298N is an industry-standard, monolithic integrated circuit designed to drive high-voltage, high-current inductive loads such as relays, solenoids, DC motors, and bipolar stepper motors. It features a **Dual H-Bridge** topology, allowing independent bidirectional control of two discrete DC motors simultaneously.

Unlike modern motor drivers that utilize highly efficient MOSFETs, the L298N is built upon legacy **Bipolar Junction Transistor (BJT)** architecture. This fundamental silicon difference defines its operating limitations, specifically regarding severe voltage drop and massive thermal power dissipation.

## 2. Hardware Topology and Interface Pins

The standard L298N breakout module abstracts the 15-pin Multiwatt integrated circuit into a standardized terminal block layout.

```text
> L298N MODULE PINOUT AND WIRING TOPOLOGY

   [Motor A Output]                              [Motor B Output]
     (OUT1, OUT2)                                  (OUT3, OUT4)
          │                                              │
      ┌───┴────────── L298N DRIVER MODULE ───────────────┴───┐
      │  [=] Heatsink                                        │
      │                                                      │
      │  [ENA] [IN1] [IN2] [IN3] [IN4] [ENB]                 │
      │    │     │     │     │     │     │                   │
      └──┬─┴─────┴─────┴─────┴─────┴─────┴─┬─────────────────┘
         │                                 │
     [12V / VCC]         [GND]         [5V Logic]
 (Drive Power Supply)   (Common)    (Logic Output/Input)

```

### 2.1 Power Domain Terminals

* **12V / VCC (Motor Power Supply):** The high-current input rail that provides kinetic power to the motors. Rated up to $35\text{V}$ absolute maximum, though typically operated between $6\text{V}$ and $24\text{V}$.
* **GND (Common Ground):** Must be tied to the high-power battery ground *and* the low-voltage microcontroller logic ground to establish a common zero-volt reference plane.
* **5V Logic Terminal:** The L298N requires a stable $5\text{V}$ supply to operate its internal logic gates. Most breakout boards include an onboard $7805$ linear voltage regulator.
* *Jumper ON:* The module derives its $5\text{V}$ logic internally from the 12V terminal. The 5V terminal becomes an *output* that can power the MCU.
* *Jumper OFF:* The internal regulator is bypassed (required if motor supply $> 12\text{V}$ to prevent 7805 thermal death). The 5V terminal becomes an *input*, requiring external 5V from the MCU.



### 2.2 Logic Control Pins

* **ENA & ENB (Enable Pins):** Control the velocity of Motor A and Motor B via PWM signals. If left bridged high with jumpers, the motor runs at 100% full unmodulated power.
* **IN1, IN2, IN3, IN4 (Direction Control):** Standard digital logic pins that dictate the H-Bridge commutation states for directional rotation.

## 3. BJT Voltage Drop and Thermal Mathematics

Because the L298N uses BJTs instead of MOSFETs, current must flow through the NPN/PNP semiconductor junctions. These junctions do not behave like simple resistors; they enforce a rigid saturation voltage drop ($V_{CE(\text{sat})}$).

Current flowing through the motor must pass through *two* transistors simultaneously (one high-side, one low-side). The total voltage drop subtracted from the motor supply is:

$$V_{\text{drop\_total}} = V_{CE(\text{sat\_high})} + V_{CE(\text{sat\_low})}$$

According to the L298N datasheet, at $1.0\text{A}$ of current, the combined maximum voltage drop is approximately $3.2\text{V}$. At $2.0\text{A}$, it approaches $4.9\text{V}$.

### 3.1 Voltage Translation Effect

If you power the L298N with a $7.4\text{V}$ LiPo battery and drive a motor at $1.5\text{A}$, the motor does not receive $7.4\text{V}$.

$$V_{\text{motor\_actual}} = V_{\text{battery}} - V_{\text{drop\_total}} \approx 7.4\text{V} - 3.5\text{V} = 3.9\text{V}$$

### 3.2 Thermal Power Dissipation Calculation

This "lost" voltage is not erased; the laws of thermodynamics dictate it is converted entirely into waste heat within the silicon die.

$$P_{\text{loss}} = V_{\text{drop\_total}} \times I_{\text{motor}}$$

If driving two motors simultaneously at $1.5\text{A}$ each ($3.0\text{A}$ total):

$$P_{\text{loss}} = 3.5\text{V} \times 3.0\text{A} = 10.5\text{ Watts of pure heat}$$

This massive thermal load is why the L298N is strictly bound to its large extruded aluminum heatsink. Without the heatsink, $10.5\text{W}$ would instantly drive the silicon temperature past its absolute maximum junction threshold ($150^\circ\text{C}$), triggering catastrophic thermal shutdown or physical destruction.

## 4. Commutation Logic Truth Table

The direction of current flow is controlled by establishing opposing logic states on the IN pairs.

| ENA (PWM) | IN1 (Logic) | IN2 (Logic) | Motor A Physical State |
| --- | --- | --- | --- |
| `HIGH` | `HIGH` | `LOW` | **Forward** (Current OUT1 $\rightarrow$ OUT2) |
| `HIGH` | `LOW` | `HIGH` | **Reverse** (Current OUT2 $\rightarrow$ OUT1) |
| `HIGH` | `LOW` | `LOW` | **Fast Motor Stop** (Dynamic Braking / Shorted to GND) |
| `HIGH` | `HIGH` | `HIGH` | **Fast Motor Stop** (Dynamic Braking / Shorted to VCC) |
| `LOW` | `X` | `X` | **Free Running Motor Stop** (Outputs disabled / Coasting) |

*Note: The exact physical direction (CW or CCW) labeled as "Forward" depends strictly on the physical polarity of the copper wires attached to OUT1 and OUT2.*

## 5. Bare-Metal C++ Firmware Integration

This implementation abstracts the dual H-bridge topology into a cohesive C++ class, allowing precise duty-cycle velocity injection and rigid direction mapping without polluting the main execution loop.

```cpp
#include <Arduino.h>

class DualL298N {
private:
    uint8_t pin_ENA, pin_IN1, pin_IN2; // Motor A
    uint8_t pin_ENB, pin_IN3, pin_IN4; // Motor B

public:
    // Constructor maps physical silicon to logic parameters
    DualL298N(uint8_t enA, uint8_t in1, uint8_t in2, 
              uint8_t enB, uint8_t in3, uint8_t in4) 
        : pin_ENA(enA), pin_IN1(in1), pin_IN2(in2),
          pin_ENB(enB), pin_IN3(in3), pin_IN4(in4) {}

    void initialize() {
        // Configure GPIO internal data direction registers as outputs
        pinMode(pin_ENA, OUTPUT); pinMode(pin_IN1, OUTPUT); pinMode(pin_IN2, OUTPUT);
        pinMode(pin_ENB, OUTPUT); pinMode(pin_IN3, OUTPUT); pinMode(pin_IN4, OUTPUT);
        
        // Assert safe initial state (Braked)
        brake_all();
    }

    void drive_motor_A(int16_t velocity) {
        // Constrain velocity bounds strictly to 8-bit timer limits
        velocity = constrain(velocity, -255, 255);
        
        if (velocity > 0) {
            digitalWrite(pin_IN1, HIGH);
            digitalWrite(pin_IN2, LOW);
            analogWrite(pin_ENA, velocity);
        } else if (velocity < 0) {
            digitalWrite(pin_IN1, LOW);
            digitalWrite(pin_IN2, HIGH);
            analogWrite(pin_ENA, abs(velocity));
        } else {
            digitalWrite(pin_IN1, LOW);
            digitalWrite(pin_IN2, LOW);
            analogWrite(pin_ENA, 0);
        }
    }

    void drive_motor_B(int16_t velocity) {
        velocity = constrain(velocity, -255, 255);
        if (velocity > 0) {
            digitalWrite(pin_IN3, HIGH);
            digitalWrite(pin_IN4, LOW);
            analogWrite(pin_ENB, velocity);
        } else if (velocity < 0) {
            digitalWrite(pin_IN3, LOW);
            digitalWrite(pin_IN4, HIGH);
            analogWrite(pin_ENB, abs(velocity));
        } else {
            digitalWrite(pin_IN3, LOW);
            digitalWrite(pin_IN4, LOW);
            analogWrite(pin_ENB, 0);
        }
    }

    void brake_all() {
        // Assert identical low states to short motor terminals for rapid deceleration
        digitalWrite(pin_IN1, LOW); digitalWrite(pin_IN2, LOW);
        digitalWrite(pin_IN3, LOW); digitalWrite(pin_IN4, LOW);
        analogWrite(pin_ENA, 0);    analogWrite(pin_ENB, 0);
    }
};

// Global Instance Initialization (Assuming standard PWM pins 5, 6)
DualL298N chassis_driver(5, 7, 8, 6, 9, 10);

void setup() {
    chassis_driver.initialize();
}

void loop() {
    // Drive chassis forward at ~75% duty cycle
    chassis_driver.drive_motor_A(190);
    chassis_driver.drive_motor_B(190);
    delay(2000);

    // Hard brake to halt kinetic momentum
    chassis_driver.brake_all();
    delay(500);

    // Reverse chassis at 100% duty cycle
    chassis_driver.drive_motor_A(-255);
    chassis_driver.drive_motor_B(-255);
    delay(2000);
}

```

## 6. Summary Summary Checklist

1. **BJT Topology Reality:** The L298N relies on legacy Bipolar Junction Transistors, which are functionally inferior to modern MOSFET designs regarding thermal efficiency and internal resistance.
2. **Voltage Starvation:** Due to $V_{CE(\text{sat})}$ transistor logic, the module will subtract approximately $2\text{V}$ to $4\text{V}$ from the primary power rail before it reaches the motor terminals.
3. **Thermal Load Dispersal:** The subtracted voltage translates directly into high thermal wattage ($P = V \times I$), mandating the heavy aluminum heatsink to prevent rapid silicon death.
4. **Logic Power Segregation:** The onboard $7805$ linear regulator drops the high-voltage battery input down to $5\text{V}$ to drive the IC's logic. It must be bypassed (jumper removed) if the motor rail exceeds $12\text{V}$.
5. **Common Ground Mandate:** Failure to physically wire the driver ground terminal to the microcontroller ground rail will result in floating logic states and erratic H-bridge commutation.
6. **Velocity via Enable Pin:** Speed regulation is achieved by injecting an 8-bit single-slope Fast PWM wave ($0$ to $255$) directly into the ENA/ENB hardware pins.
7. **Braking vs. Coasting:** Pulling both direction pins `LOW` shorts the motor leads, creating heavy electromagnetic drag for rapid braking. Pulling the enable pin `LOW` while leaving direction states intact allows free-wheeling coasting.
8. **Class Abstraction:** Wrapping dual H-bridge pin logic into a structured C++ class removes redundant `digitalWrite` calls from the execution loop, ensuring robust and readable firmware architectures.
