# 09.04 - PWM Control: Timer Peripheral Architectures, Prescalers, and Hardware Waveform Generation

## 1. Silicon-Level Hardware Timer Subsystems

While pulse width modulation (PWM) signals can be generated through software bit-banging loops that manually toggle a General-Purpose Input/Output (GPIO) pin high and low, this brute-force approach consumes near $100\%$ of the CPU's processing power. In modern embedded system design, PWM waveforms are synthesized entirely within specialized hardware blocks called **Timer/Counter Peripherals**.

Once configured by software registers, these peripheral blocks run completely independently of the main CPU execution thread, generating highly accurate, jitter-free high-frequency control signals without consuming clock cycles from the primary application loop.

```text
> HARDWARE TIMER INTEGRATION CORE FLOW

  [ Clock Source ] ──► [ Prescaler Counter ] ──► [ Timer Register (TCNTx) ]
  (System Oscillator)   (Frequency Divider)       (Main Binary Counter)
                                                          │
  [ Output Pin (OCx) ] ◄── [ Output Compare Unit ] ◄──────┘
  (Generated PWM Wave)      (Compares TCNTx == OCRx)

```

### 1.1 Structural Timer Peripheral Blocks

A silicon-level hardware timer peripheral consists of four fundamental structural sub-modules:

* **The Main Counter Register ($TCNTx$):** A dedicated, hardware-driven binary upward/downward counter register that increments or decrements its stored value by one every time it receives a clock pulse.
* **The Clock Prescaler:** A programmable frequency divider network positioned between the primary system oscillator clock and the timer counter register, scaling down the raw clock speed to manageable operational ranges.
* **The Output Compare Register ($OCRx$):** A read/write configuration register used to hold a fixed target binary threshold value written by the user application.
* **The Output Compare Unit & Comparator:** A hardware-level digital comparator network that continuously matches the instantaneous real-time value of the running counter ($TCNTx$) against the static threshold value stored in the output compare register ($OCRx$). When the values match ($TCNTx = OCRx$), the comparator instantly fires a hardware signal that triggers an **Output Compare Match**. This match toggles the physical state of the associated external output pin without any software intervention.

## 2. Prescaler Dynamics and Governing Frequency Scaling Formulas

The fundamental system oscillator clock frequency ($f_{\text{clk\_I/O}}$) of a microcontroller is often too high for low-to-medium-speed hardware control applications like driving servo motors or thermal heating elements. To reduce the counting speed of the timer, the clock signal is fed through a **Prescaler**.

The prescaler uses internal flip-flop frequency divider circuits to divide the incoming clock frequency by a fixed binary factor ($N$), such as $1, 8, 64, 256, \text{ or } 1024$.

```text
> HARDWARE PRESCALER SYSTEM OSCILLATOR CLOCK SIGNAL DIVISIONS

  Raw System Clock (f_clk) █  █  █  █  █  █  █  █  █  █  █  █  █  █  █  █
                           ◄─────────────── 16 MHz ───────────────►
  Prescaled Clock (N = 8)  █▀▀▀▀▀▀▀▀█▄▄▄▄▄▄▄▄█▀▀▀▀▀▀▀▀█▄▄▄▄▄▄▄▄█▀▀▀▀▀▀▀▀
                           ◄──────────────── 2 MHz ────────────────►

```

### 2.1 The Clock Prescaler & Timer Frequency Formula

The resulting effective **Timer Counting Frequency** ($f_{\text{timer}}$) dictates exactly how fast the main counter register ($TCNTx$) increments:

$$f_{\text{timer}} = \frac{f_{\text{clk\_I/O}}}{N}$$

* $f_{\text{timer}}$ = **Effective clock frequency operating the counter**, measured in Hertz ($\text{Hz}$).
* $f_{\text{clk\_I/O}}$ = **Primary internal system clock source oscillator frequency** (e.g., $16\text{ MHz}$ on standard ATmega328P MCUs), measured in Hertz ($\text{Hz}$).
* $N$ = **Selected prescaler division factor ratio** ($1, 8, 64, 256, \text{ or } 1024$).

The exact physical duration of a single discrete counting increment step ($\Delta t_{\text{step}}$) is the mathematical inverse of the timer frequency:

$$\Delta t_{\text{step}} = \frac{1}{f_{\text{timer}}} = \frac{N}{f_{\text{clk\_I/O}}}$$

#### Physical Application Context

If a system runs a $16\text{ MHz}$ clock and you select a prescaler of $N = 64$, the timer frequency becomes:

$$f_{\text{timer}} = \frac{16,000,000\text{ Hz}}{64} = 250,000\text{ Hz} = 250\text{ kHz}$$

This means the physical duration of a single discrete counting increment step ($\Delta t_{\text{step}}$) equals:

$$\Delta t_{\text{step}} = \frac{1}{250,000\text{ Hz}} = 4\text{ }\mu\text{s}$$

## 3. Hardware Waveform Generation Operational Modes

Hardware timers can be configured into several standard waveform generation modes, altering how the counter register interacts with the comparator unit to produce different PWM signal behaviors.

### 3.1 Fast PWM Mode (Single-Slope Counting)

Fast PWM mode provides high-frequency waveform generation. The main counter register ($TCNTx$) behaves as a **Single-Slope Counter**, incrementing upward from zero ($0x00$) until it hits its absolute maximum resolution limit ceiling ($TOP$, typically $255$ or $0xFF$ for an 8-bit timer).

The moment the counter passes $TOP$, it instantly resets back down to zero ($0x00$) in a single clock cycle and begins climbing upward again.

```text
> FAST PWM SINGLE-SLOPE HARDWARE COUNTER WAVEFORM GEOMETRY

  Counter Value (TCNTx)
     ▲
  TOP│      /|      /|      /|      /|
     │     / |     / |     / |     / |
  OCR│────/──┼────/──┼────/──┼────/──┼────  ◄── Compare Match Threshold
     │   /   |   /   |   /   |   /   |
    0┼──┴────┴──┴────┴──┴────┴──┴────┴────────► Time (t)
     │   ▲   ▲   ▲   ▲
  PIN│───┐   ┌───┐   ┌───┐   ┌───┐   ┌────
     └───┴───┴───┴───┴───┴───┴───┴───┴────  ◄── Resulting Output Waveform
         ◄─t_on─►

```

#### Non-Inverting Fast PWM Logic

* When the counter register ($TCNTx$) resets to zero, the hardware automatically forces the external output pin ($OCx$) to a **Logic High** ($1$) state.
* The counter counts upward. The moment a compare match occurs ($TCNTx = OCRx$), the hardware instantly drives the output pin down to a **Logic Low** ($0$) state.
* The pin remains Low until the counter rolls over at $TOP$, where it resets to zero and drives the output pin back High.

#### Fast PWM Frequency Formula

The fundamental output switching frequency ($f_{\text{Fast\_PWM}}$) for an 8-bit single-slope counter mode is calculated as follows:

$$f_{\text{Fast\_PWM}} = \frac{f_{\text{clk\_I/O}}}{N \cdot 256}$$

* **$256$ (Total Discrete Steps):** Because an 8-bit counter tracks values from $0$ to $255$, it must execute exactly $256$ discrete counting ticks to complete one full single-slope ramp cycle from ground up to $TOP$ and back to zero.

#### Physical Application Context

Using a $16\text{ MHz}$ clock and a prescaler of $N = 64$, the output frequency of a Fast PWM wave is calculated as:

$$f_{\text{Fast\_PWM}} = \frac{16,000,000\text{ Hz}}{64 \cdot 256} = \frac{16,000,000}{16,384} \approx 976.56\text{ Hz}$$

### 3.2 Phase Correct PWM Mode (Dual-Slope Counting)

Phase Correct PWM mode provides a highly symmetrical, stable waveform layout. The counter register ($TCNTx$) is configured to operate as a **Dual-Slope Counter**, continuously counting upward from zero to $TOP$, and then immediately changing direction to count downward from $TOP$ back to zero.

```text
> PHASE CORRECT PWM DUAL-SLOPE HARDWARE COUNTER GEOMETRY

  Counter Value (TCNTx)
     ▲
  TOP│    /\      /\      /\      /\
     │   /  \    /  \    /  \    /  \
  OCR│──/────\──/────\──/────\──/────\───   ◄── Compare Match Threshold
     │ /      \/      \/      \/      \
    0┼┴────────┴───────┴───────┴────────► Time (t)
     │    ▲        ▲
  PIN│────┐        ┌──────┐        ┌─────
     └────┴────────┴──────┴────────┴─────   ◄── Symmetrical Output Waveform
          ◄──t_on──►

```

#### Non-Inverting Phase Correct PWM Logic

* As the counter counts upward from zero, the output pin starts in a **Logic High** ($1$) state.
* When the counter hits the compare threshold ($TCNTx = OCRx$) while climbing up, the output pin is driven to a **Logic Low** ($0$) state.
* The counter hits $TOP$ and reverses direction, counting downward. When it hits the compare threshold ($TCNTx = OCRx$) a second time on its way down, the output pin is driven back to a **Logic High** ($1$) state.

#### Phase Correct PWM Frequency Formula

Because the counter must traverse the entire register resolution block twice (Up and down) to complete a single signal cycle, the total wave period doubles. This cuts the output frequency ($f_{\text{Phase\_Correct}}$) exactly in half compared to Fast PWM mode:

$$f_{\text{Phase\_Correct}} = \frac{f_{\text{clk\_I/O}}}{N \cdot 510}$$

* **$510$ (Total Double-Slope Steps):** To complete one full periodic wave cycle, the counter must climb up ($0 \rightarrow 255$, taking $255$ steps) and descend back down ($255 \rightarrow 0$, taking another $255$ steps). The combined total steps required per cycle is $255 + 255 = 510$ discrete steps.

#### Physical Application Context

Using identical prescaler attributes ($N = 64$) and a $16\text{ MHz}$ system clock, the Phase Correct PWM output wave frequency is calculated as:

$$f_{\text{Phase\_Correct}} = \frac{16,000,000\text{ Hz}}{64 \cdot 510} = \frac{16,000,000}{32,640} \approx 490.20\text{ Hz}$$

## 4. Architectural Control Registers and Low-Level Manipulation

To configure and operate hardware PWM on a microcontroller, software applications interact directly with specific internal memory-mapped control registers.

Using the 8-bit **Timer/Counter 0** peripheral of the Microchip AVR (ATmega328P) architecture as an industry-standard reference model, three primary hardware register blocks must be modified:

```text
> AVR 8-BIT TIMER 0 HARDWARE CONFIGURATION REGISTERS

  Timer/Counter Control Register A [ TCCR0A ] ──► Configures Waveform Mode (Fast, Phase Correct) & Compare Pin Actions
  Timer/Counter Control Register B [ TCCR0B ] ──► Configures Clock Source Connections & Prescaler Division Select Bits
  Output Compare Register 0 A     [ OCR0A  ] ──► Holds 8-Bit Target Value (0-255) to Control Output Pulse Width

```

### 4.1 Low-Level Register Configuration Code Examples

Direct register access allows developers to establish exact timing controls without the processing overhead of high-level runtime abstraction frameworks.

```c
// Direct Low-Level AVR C Timer 0 Configuration Example

void configure_hardware_pwm(void) {
    // 1. Configure the physical I/O pin associated with Timer 0 Compare Channel A as an output
    // On the ATmega328P, Timer 0 Channel A maps to Port D Pin 6 (Digital Pin 6)
    DDRD |= (1 << 6);

    // 2. Set TCCR0A to configure Non-Inverting Fast PWM Mode
    // Clear COM0A0 (Bit 6) and Set COM0A1 (Bit 7) -> Configures non-inverting compare mode behavior
    // Set WGM00 (Bit 0) and Set WGM01 (Bit 1)    -> Selects Fast PWM generation mode with TOP = 255
    TCCR0A = (1 << COM0A1) | (1 << WGM01) | (1 << WGM00);

    // 3. Set TCCR0B to select the Prescaler Division Factor
    // Set CS01 (Bit 1) and Set CS00 (Bit 0) -> Selects a prescaler division factor of N = 64
    // With a 16 MHz system oscillator, f_pwm = 16MHz / (64 * 256) = 976.56 Hz switching speed
    TCCR0B = (1 << CS01) | (1 << CS00);

    // 4. Assign the duty cycle threshold value to Output Compare Register 0 A
    // Setting OCR0A to 128 creates a balanced 50% duty cycle ratio (128 / 255 ≈ 50%)
    OCR0A = 128;
}

void adjust_duty_cycle(uint8_t duty_step) {
    // Dynamically adjust the output compare match threshold to alter pulse width duration
    OCR0A = duty_step; 
}

```

## 6. Summary Summary Checklist

1. **Hardware Independence:** Silicon-level timer peripherals run completely independently of the main CPU execution thread, generating highly accurate, jitter-free PWM signals without consuming system processing overhead.
2. **Main Counter Progress:** The main counter register acts as a hardware-driven binary accumulator that increments or decrements automatically on every incoming clock pulse.
3. **Prescaler Division Rules:** Prescalers act as binary clock frequency dividers, scaling down high-frequency system oscillator clocks by a fixed factor ($N$) to yield the target timer counting speed.
4. **Compare Match Triggers:** Digital comparators continuously match active counter values against user-configured threshold registers, instantly triggering a hardware output pin toggle upon an exact value match.
5. **Single-Slope Tracking:** Fast PWM mode utilizes a single-slope counting structure where the register counts upward from zero to its maximum limit before instantly resetting back to zero.
6. **Dual-Slope Symmetry:** Phase Correct PWM mode relies on a dual-slope counting structure that counts smoothly up to its maximum ceiling and then reverses direction down to zero, producing highly symmetrical wave profiles.
7. **Frequency Discrepancies:** Because dual-slope counters traverse their register resolution block twice per cycle, Phase Correct PWM frequencies operate at exactly half the speed of equivalent Fast PWM configurations.
8. **Low-Level Register Settings:** Embedded applications configure hardware timers by modifying dedicated configuration registers that select the waveform generation mode and prescaler factor.
9. **Dynamic Duty Manipulation:** Dynamically updating the binary value stored inside the output compare register instantly changes the compare match timing, altering the output pulse width at runtime.
10. **Application Domain Split:** High-frequency single-slope Fast PWM is ideal for driving static electrical loads like LEDs and power grids, whereas symmetrical dual-slope Phase Correct PWM is optimized for smooth, low-noise electric motor control.
