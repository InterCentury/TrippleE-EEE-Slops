# 10.01 - Motor Actuation Systems: DC, Servo, and Stepper Integration

## 1. Electromechanical Actuation Modalities

Microcontrollers cannot execute physical work directly. To translate digital logic into kinetic motion, embedded systems rely on electromechanical actuators—motors. Because motors require voltage and current levels far exceeding the physical destruction limits of an MCU’s General-Purpose Input/Output (GPIO) pins, intermediary **Motor Driver** hardware is universally required to isolate the logic circuitry from the high-power traction rails.

Robotic articulation relies on three primary motor topologies, each serving a distinct mechanical paradigm:

1. **Direct Current (DC) Motors:** Continuous rotational velocity.
2. **Servo Motors:** Closed-loop absolute angular positioning.
3. **Stepper Motors:** Open-loop discrete angular displacement.

## 2. DC Motors & H-Bridge Bidirectional Control

A standard brushed DC motor spins continuously when a voltage is applied across its two terminals. The rotational velocity is proportional to the applied voltage, and the direction of rotation is dictated by the electrical polarity.

### 2.1 The H-Bridge Switching Topology

To achieve bidirectional control from a single-polarity power supply, a switching matrix known as an **H-Bridge** is utilized. It consists of four solid-state switches (transistors or MOSFETs) arranged in an 'H' configuration around the central motor payload.

```text
> H-BRIDGE SOLID-STATE SWITCHING MATRIX

       External Motor Power Supply Rail (V_MOTOR)
                           │
             ┌─────────────┴─────────────┐
             │                           │
  [ Switch 1 (High-Side) ]    [ Switch 3 (High-Side) ]
             │                           │
             ├─────── [ DC MOTOR ] ──────┤
             │                           │
  [ Switch 2 (Low-Side) ]     [ Switch 4 (Low-Side) ]
             │                           │
             └─────────────┬─────────────┘
                           │
               System Ground Floor (GND)

```

#### Directional Logic States

* **Forward Rotation:** S1 and S4 are CLOSED. S2 and S3 are OPEN. Current flows left-to-right through the motor coil.
* **Reverse Rotation:** S3 and S2 are CLOSED. S1 and S4 are OPEN. Current flows right-to-left through the motor coil.
* **Dynamic Braking:** S2 and S4 are CLOSED. S1 and S3 are OPEN. The motor terminals are shorted together, converting the motor into a heavily loaded generator to halt momentum instantly.
* **Shoot-Through (Catastrophic Fault):** S1 and S2 (or S3 and S4) are CLOSED simultaneously. This creates a direct dead-short from $V_{\text{MOTOR}}$ to GND, instantly destroying the silicon switches. Hardware drivers usually contain internal logic gates to prevent this state.

### 2.2 Velocity Control via PWM

Velocity is governed by injecting a high-frequency PWM signal into the active switch gates. The effective voltage delivered to the coils ($V_{\text{eff}}$) is a function of the duty cycle ($D$):

$$V_{\text{eff}} = V_{\text{MOTOR}} \cdot D = V_{\text{MOTOR}} \cdot \left( \frac{\text{PWM}_{\text{value}}}{255} \right)$$

### 2.3 Bare-Metal DC Motor Implementation (L298N/TB6612FNG)

```cpp
#define MOTOR_IN1_PIN 4  // Direction Control A
#define MOTOR_IN2_PIN 5  // Direction Control B
#define MOTOR_EN_PIN  6  // PWM Velocity Control (Timer 0)

void setup() {
    pinMode(MOTOR_IN1_PIN, OUTPUT);
    pinMode(MOTOR_IN2_PIN, OUTPUT);
    pinMode(MOTOR_EN_PIN, OUTPUT);
}

void drive_motor(int speed, bool forward) {
    // 1. Establish rotational polarity
    if (forward) {
        digitalWrite(MOTOR_IN1_PIN, HIGH);
        digitalWrite(MOTOR_IN2_PIN, LOW);
    } else {
        digitalWrite(MOTOR_IN1_PIN, LOW);
        digitalWrite(MOTOR_IN2_PIN, HIGH);
    }
    
    // 2. Inject velocity duty cycle
    analogWrite(MOTOR_EN_PIN, speed); // speed range: 0 to 255
}

void brake_motor() {
    // Short low-side switches to halt momentum
    digitalWrite(MOTOR_IN1_PIN, LOW);
    digitalWrite(MOTOR_IN2_PIN, LOW);
    analogWrite(MOTOR_EN_PIN, 255);
}

```

## 3. Servo Motors & Absolute Position Control

A standard hobby servo motor does not spin continuously. It maps a specific control signal to a physical angle (typically bounded between $0^\circ$ and $180^\circ$). It achieves this via a closed-loop system: an internal DC motor is geared down for high torque, and its output shaft is physically linked to a potentiometer. An internal microcontroller compares the potentiometer's feedback voltage against the incoming control signal and drives the motor until the physical error resolves to zero.

### 3.1 Standard 50Hz Pulse-Width Signaling

Servos are controlled using a strictly timed square wave operating at a fixed **50 Hz** frequency (a $20\text{ ms}$ periodic cycle). The physical angle is dictated solely by the high-time duration ($T_{\text{pulse}}$) of the pulse, *not* the duty cycle percentage.

```text
> 50Hz SERVO MOTOR TIMING PROTOCOL (20ms Period)

  1.0 ms Pulse Width ──► Drives shaft to absolute 0° position.
  ███                    (Minimum limit)
  ┼──────────────────────────────────────────────────────────► (20ms)

  1.5 ms Pulse Width ──► Drives shaft to absolute 90° position.
  █████                  (Neutral center limit)
  ┼──────────────────────────────────────────────────────────► (20ms)

  2.0 ms Pulse Width ──► Drives shaft to absolute 180° position.
  ███████                (Maximum limit)
  ┼──────────────────────────────────────────────────────────► (20ms)

```

The mathematical mapping for the pulse width ($T_{\text{pulse}}$) relative to the desired angle ($\theta$) is:

$$T_{\text{pulse}} = 1000\text{ }\mu\text{s} + \left( \frac{\theta}{180^\circ} \times 1000\text{ }\mu\text{s} \right)$$

### 3.2 Standard API Servo Implementation

```cpp
#include <Servo.h>

#define SERVO_SIGNAL_PIN 9 // Must support hardware timer interrupts

Servo steering_servo;

void setup() {
    // Attach the servo logic to the target pin
    steering_servo.attach(SERVO_SIGNAL_PIN);
    
    // Initialize to neutral center
    steering_servo.write(90); 
}

void sweep_sweep() {
    // Traverse from 0 to 180 degrees
    for (uint8_t pos = 0; pos <= 180; pos++) {
        steering_servo.write(pos);
        delay(15); // Allow mechanical transit time
    }
}

```

## 4. Stepper Motors & Discrete Phase Sequencing

Stepper motors divide a full $360^\circ$ rotation into a massive number of equal, discrete steps. They do not possess internal feedback mechanisms (open-loop) but provide extreme precision for 3D printers and CNC machines. Movement is achieved by energizing internal electromagnetic stator coils in a strict sequential pattern.

### 4.1 Step Angle Mathematics

The fundamental precision of a stepper motor is defined by its step angle ($\theta_{\text{step}}$). Standard industrial steppers feature a $1.8^\circ$ step angle.

$$N_{\text{steps}} = \frac{360^\circ}{\theta_{\text{step}}}$$

For a $1.8^\circ$ motor, $N_{\text{steps}} = 200$. Therefore, to rotate the shaft exactly one full revolution, the microcontroller must issue exactly 200 sequential electrical pulses.

### 4.2 Bipolar Stepper Control via Step/Dir Drivers (A4988)

Because generating complex multi-phase overlapping square waves directly from the MCU is computationally heavy, modern robotics rely on integrated driver chips like the A4988 or DRV8825. These drivers abstract the complex phase logic into two simple digital inputs: `STEP` and `DIR`.

```text
> STEP/DIR HARDWARE ABSTRACTION TOPOLOGY

  [ MCU ]                  [ A4988 Driver ]                [ Stepper Motor ]
  Pin 2 ──(Direction)──►     [ DIR ]                         [ Coil A1 ]
  Pin 3 ──(PWM Pulse)──►     [ STEP ]  ──(High Current)──►   [ Coil A2 ]
                             [ EN ]                          [ Coil B1 ]
                             [ VMOT] ◄──(24V Rail)           [ Coil B2 ]

```

### 4.3 Bare-Metal Stepper Driver Implementation

```cpp
#define DIR_PIN  2
#define STEP_PIN 3
#define EN_PIN   4

const int STEPS_PER_REV = 200; // Standard 1.8-degree motor

void setup() {
    pinMode(DIR_PIN, OUTPUT);
    pinMode(STEP_PIN, OUTPUT);
    pinMode(EN_PIN, OUTPUT);
    
    // Pull Enable Low to activate the driver phase FETs
    digitalWrite(EN_PIN, LOW); 
}

void step_motor(int steps, int microsecond_delay) {
    // 1. Set Direction based on the sign of the steps integer
    digitalWrite(DIR_PIN, (steps > 0) ? HIGH : LOW);
    
    int absolute_steps = abs(steps);

    // 2. Generate the required number of discrete square wave pulses
    for (int i = 0; i < absolute_steps; i++) {
        digitalWrite(STEP_PIN, HIGH);
        delayMicroseconds(microsecond_delay); // Determines velocity
        digitalWrite(STEP_PIN, LOW);
        delayMicroseconds(microsecond_delay);
    }
}

void loop() {
    // Rotate 1 full revolution clockwise at moderate speed
    step_motor(STEPS_PER_REV, 1000);
    delay(500);
    
    // Rotate 2 full revolutions counter-clockwise at high speed
    step_motor(-2 * STEPS_PER_REV, 400);
    delay(500);
}

```

## 5. Summary Summary Checklist

1. **Isolation Mandate:** Microcontrollers must never drive motors directly; dedicated driver modules are required to handle high-current loads and prevent inductive kickback damage.
2. **H-Bridge Architecture:** DC motor direction is inverted using a four-switch H-bridge array, allowing bipolar current flow from a single unipolar power supply.
3. **Shoot-Through Catastrophe:** Simultaneously closing the high-side and low-side switches on the same half of an H-bridge causes a fatal dead-short circuit.
4. **DC Velocity Control:** Rotational speed in DC motors is proportionally controlled by scaling the duty cycle of a PWM signal injected into the H-bridge enable pin.
5. **Servo Closed-Loop Mechanics:** Servo motors achieve precise angular positioning by constantly comparing the physical shaft position (via internal potentiometer) against the requested signal.
6. **Time-Domain Servo Signaling:** Servo position is dictated purely by the microsecond duration of a 50Hz high pulse ($1.0\text{ ms} = 0^\circ, 1.5\text{ ms} = 90^\circ, 2.0\text{ ms} = 180^\circ$).
7. **Stepper Open-Loop Actuation:** Stepper motors operate without feedback, relying on precise phase excitation sequences to lock the rotor into discrete angular positions.
8. **Step Angle Resolution:** Standard stepper motors feature a $1.8^\circ$ step angle, mathematically requiring exactly $200$ electrical pulses to complete one $360^\circ$ revolution.
9. **Driver Abstraction:** Modern stepper drivers abstract complex coil sequencing logic into a two-pin `STEP/DIR` interface, vastly reducing MCU computational overhead.
10. **Velocity via Pulse Delay:** Stepper motor velocity is controlled inversely by the microsecond delay injected between `STEP` pin toggles; shorter delays yield higher RPMs.
